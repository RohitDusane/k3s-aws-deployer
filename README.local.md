# Fintech Risk Scoring MLOps API

A production-oriented **MLOps API for fintech risk scoring**, designed with a standardized architecture for containerization, orchestration, deployment, and monitoring.

This project is an **adaptation and extension** inspired by the work of **Amir Hossein Honardoust** and the original [Financial-Fraud-Risk-Engine](https://github.com/AmirhosseinHonardoust/Financial-Fraud-Risk-Engine).

The project extends the original concept with a **Dockerized application**, **Kubernetes-based deployment**, and a foundation for **Prometheus monitoring**, demonstrating how a machine-learning risk scoring service can be prepared for a modern production environment.

## Key Technologies

- Python
- FastAPI
- Machine Learning
- Docker
- Kubernetes
- Prometheus
- GitHub Actions
- AWS
- Amazon ECR
- Amazon EKS

## Project Goals

- Expose the risk-scoring model through a REST API
- Containerize the application using Docker
- Deploy and manage the application with Kubernetes
- Implement health checks and production-ready configuration
- Add monitoring and observability using Prometheus
- Establish CI/CD using GitHub Actions
- Use AWS ECR for container image management
- Deploy the application to AWS infrastructure

## Running Locally

Create a virtual environment:

```bash
python -m venv venv
```

Activate it on Windows:

```bash
venv\Scripts\activate
```

Install dependencies:

```bash
pip install -r requirements.txt
```

Run the API:

```bash
uvicorn src.main:app --reload
```

The API will be available at:

```text
http://localhost:8000
```

Swagger/OpenAPI documentation:

```text
http://localhost:8000/docs
```

## Running with Docker

Build the image:

```bash
docker build -t risk-mlops .
```

Run the container:

```bash
docker run -p 8000:8000 risk-mlops
```

Access the API:

```text
http://localhost:8000
```

### K3s start-stop
12. How to stop everything later
Stop K3s
Inside Ubuntu:

sudo systemctl stop k3s

This stops your Kubernetes workloads.

Check:

sudo systemctl status k3s

Start it again
sudo systemctl start k3s

Then:

sudo k3s kubectl get nodes

Your Kubernetes resources should come back because they're stored in the cluster.

Stop Prometheus/Grafana
From PowerShell:

docker compose stop prometheus grafana

Start again:

docker compose start prometheus grafana

If you use:

docker compose down

the containers are removed, but your named volumes:

prometheus_data
grafana_data

will normally remain.

So your Grafana/Prometheus data can survive.

13. Docker Desktop itself
You do not need to keep Docker Compose running all the time.

However, because you're using WSL2 and Docker Desktop, I'd keep Docker Desktop running while you're doing this local testing, particularly if your K3s setup depends on Docker Desktop/WSL networking.

You can stop Docker Compose:

docker compose stop

without shutting down Docker Desktop.

And later:

docker compose start

14. What I want you to run now
You're actually in a good state. Don't reinstall anything.

From Ubuntu WSL, run these:

sudo k3s kubectl get pods -n risk-mlops

sudo k3s kubectl get deployment -n risk-mlops

sudo k3s kubectl get svc -n risk-mlops

sudo k3s kubectl get hpa -n risk-mlops

sudo k3s crictl images | grep risk-mlops

And, most importantly, if those two pods are still stuck:

sudo k3s kubectl describe pod risk-mlops-api-75dd4fc44-9ggzp -n risk-mlops

Paste those outputs. Then we can do the next step: expose the K3s API to your Windows browser, connect Prometheus → K3s API → Grafana, and test the complete local deployment + monitoring flow.
